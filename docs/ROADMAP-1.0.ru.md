## 0. Как читать документ

Статусы пунктов:

- `✅ Done` — реализовано в коде на срезе `1ba4cf1`, покрыто ручным/автотестом.
- `🟡 Partial` — каркас есть, но покрывает не весь пункт концепта.

## 1. Что такое v1.0

### 1.1. Цель

Быстрый (холодный старт <300 мс, ~35 МБ idle), модульный (6 крейтов), опенсорсный лаунчер на Rust
(`egui`/`eframe` + `wgpu`/`glow`), который ведёт новичка от первого запуска до игры одной кнопкой,
а продвинутому даёт инстансы уровня MultiMC/Prism — на железе вплоть до GT710, под Windows и Linux,
с нулевой телеметрией (сеть только: Mojang, Adoptium, Modrinth, CurseForge).

### 1.2. Технические рамки (не меняются в 1.0)

- Rust 2021 workspace: `amc-core`, `amc-auth`, `amc-downloader`, `amc-minecraft`, `amc-mods`, `amc-ui` + `src/main.rs`.
- GUI: `egui 0.29` + `eframe` (`wgpu` с fallback на `glow`/OpenGL 3.3+), 60–144 FPS, тёмная тема Aleph (`#080606` / `#8B1A2A`).
- Один релизный канал для пользователей (debug/release — только профили сборки, без stable/beta).
- Каждая сборка самодостаточна: дедупликации assets/библиотек между сборками нет.
- Фидбэк — только внешний сайт/GitHub, кнопки «сообщить о баге» внутри нет.
- Лаунчер не продаёт и не предлагает купить лицензию — вне задач.

### 1.3. Границы: что НЕ входит в v1.0 (`🚫 Out`)

- Общий браузер серверов. Вместо него — избранное + авто-инжект в каждую сборку (P8).
- Облачная синхронизация (WetID/облако) — будущие версии.
- Aleph Guard / античит (проверка целостности, сканирование, противодействие читам) — 2.0.
- Экспорт/шеринг сборки для других пользователей — не нужен в 1.0.
  (Но **импорт** распространённых форматов в 1.0 входит — см. P4.)
- Импорт профилей из других лаунчеров (TLauncher, MultiMC и т.д.) — не требуется вообще.
- Встроенный редактор скинов — не в 1.0 (только выбор/загрузка).
- Чат с друзьями в лаунчере — только внутриигровой чат.
- Кастомные темы — скорее всего нет (решение не финальное, `❓ Open`).
- macOS — не в приоритете (базовая поддержка, без гарантий).
- Отдельный stable/beta канал обновлений — нет.

## 2. Точка отсчёта: что уже готово (аудит `1ba4cf1`)

### `amc-core` — `✅ Done` (база)
- `types.rs`: `LoaderType` (Vanilla/Fabric/Quilt/Forge/NeoForge/OptiFine), `ReleaseType`
  (Release/Snapshot/Beta/Alpha/Old), `Instance` (create/persist `instances.json`, `clone_instance`
  с копированием `config/mods/resourcepacks/shaderpacks`, `ensure_directories` incl. `screenshots`,
  `get_game_dir` + `custom_dir`), `LaunchOptions` (RAM min/max, `java_path`, JVM args, resolution,
  fullscreen, `quick_play_server/port`), базовая статистика (`total_played_minutes`, `last_played`).
- `paths.rs`: `LauncherPaths` (`instances/versions/assets/libraries/runtimes/cache/logs`,
  `config.json/accounts.json/instances.json`), `custom()` для смены диска.
- `config.rs`: `UiSettings` (тема `aleph-dark`, scale, `close_after_launch`, фильтры версий,
  язык) + автосейв из настроек.
- `i18n.rs`: EN/RU/UK, живое переключение без рестарта, большой типизированный словарь.

### `amc-auth` — `🟡 Partial`
- `✅` Три типа (`Microsoft`/`WetID`/`Offline`), `AccountManager` (несколько аккаунтов,
  активный, персист `accounts.json`), Device Code Flow MS (запрос кода + polling),
  офлайн-ник + Offline-UUID, WetID login/password + token verify.
- `⬜` Расхождения с концептом: WetID сейчас формой логин/пароль, а должен быть **через браузер**;
  нет выбора identity при каждом запуске + «запомнить выбор»; нет запрета второго WetID;
  нет комбо-логики WetID+лицензия (см. P6).

### `amc-downloader` — `🟡 Partial`
- `✅` Параллельный движок (16 воркеров, semaphore), retry ×3, SHA-1, пропуск готовых файлов,
  побайтовый прогресс + трекер, Adoptium OpenJDK 8/17/21 (zip/tar.gz, strip top-level dir).
- `⬜` Нет паузы/возобновления, лимита скорости, очереди как UI, ETA по файлу (см. P3).

### `amc-minecraft` — `🟡 Partial`
- `✅` Манифест версий (fetch + кэш), `VersionDetails` (fetch/merge), правила/OS-arch фильтр,
  ассеты (index + объекты), `FabricLoader`/`QuiltLoader` (версия + profile + merge),
  `ForgeLoader`/`NeoForgeLoader`/`OptiFineLoader` (**только lookup версий**),
  `ArgumentBuilder` (JVM + game args), `MinecraftLauncher` (spawn, захват stdout/stderr,
  `GameEvent`), `ServerPinger` (SLP), краш-диагностика (OOM / Java / Fabric-зависимости / Mixin).
- `⬜` Запускной пайплайн в `amc-ui/src/app.rs` реально доводит только **Fabric/Quilt/Vanilla**,
  остальное падает в fallback на ваниллу — полный пайплайн Forge/NeoForge/OptiFine ещё нужен (P2/P4).

### `amc-mods` — `🟡 Partial`
- `✅` Modrinth API v2 (поиск + файл), CurseForge (поиск + файл), `LocalModManager`
  (скан `mods/`, вкл/выкл через `.disabled`, парсинг `fabric.mod.json`/`mods.toml`/`mcmod.info`),
  категории Mod/ResourcePack/Shader с раскладкой по `mods/resourcepacks/shaderpacks`.
- `⬜` Нет проверки совместимости до установки, нет фильтров (категория/популярность/версия MC),
  нет апдейтов одной кнопкой/уведомлений/rollback/pin, нет импорта `.mrpack`/Curse `.zip`, нет Discover (P4).

### `amc-ui` — `🟡 Partial`
- `✅` Sidebar/Home/Instances/Mods/Skins/Settings, TitleBar, BottomBar с аватаром из скина,
  LoginModal (3 таба), ConsoleModal (буфер 5000, поиск, autoscroll, copy, export `.log`, подсветка),
  DownloadOverlay, Home (версии + поиск + фильтры + direct connect), Instances
  (create/edit/delete/clone/select/launch, RAM/loader/version), Mods (installed/search/install),
  Skins (2D-превью Classic/Slim, загрузка PNG через `rfd`, reset Steve/Alex, export PNG),
  Settings (General/Java&Memory/Accounts: язык, поведение, resolution, папки, RAM-слайдеры,
  Java picker + reset, JVM args + пресеты G1GC/ZGC, список аккаунтов).
- `⬜` Нет first-run wizard, нет Simple/Pro режимов как разных экранов, нет шаблонов/иконок/папок-тегов
  инстансов, нет disk usage, нет менеджера загрузок, нет галереи скринов, нет бэкапа миров,
  нет избранного серверов, нет вкладки профиля (ник/скин/плащ), нет 3D-превью скина (P1–P10).

## 7. Процесс обновления (концепт продолжает меняться)

1. Изменение продукта начинается с `docs/CONCEPT.ru.md` (+ зеркало `docs/CONCEPT.md`).
2. Затем обновляется этот план (`ROADMAP-1.0.ru.md` + `ROADMAP-1.0.md`): статусы, фазы, открытые вопросы.
3. Под каждую фазу — GitHub Issue(s) с тем же номером `P<n>`; закрытие issue = приёмка фазы.
4. Непрояснённые моменты не додумываются молча: помечаются `❓ Open` здесь и в концепции до решения.
5. Коммиты, меняющие поведение: `feat(...)`/`fix(...)`; доки: `docs(...)`; смешивать код и доки в одном коммите — только если изменение атомарно (как этот).
